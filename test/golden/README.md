# Golden compression fixtures

`test/golden/*.bin` (and `payload.bin`) are byte-exact compressed RecordBatch
v2 fixtures that the MoonBit decoders must parse. They are generated by
**independent** implementations so the decoders are validated against foreign
bytes, not the project's own encoders:

- `payload.bin` — the shared uncompressed payload.
- `golden_gzip.bin` — Python's `gzip`.
- `golden_snappy.bin` / `golden_lz4.bin` / `golden_zstd.bin` — cramjam's
  Rust snappy/lz4/zstd (snappy in the xerial framing Kafka uses).

Each codec file also carries a spliced RecordBatch: the batch container comes
from the MoonBit encoder (uncompressed), then the records region is replaced
with the foreign-compressed blob and the CRC32C repaired — exactly what a
producer with that codec would put on the wire.

## Regenerating

Run from the repo root (needs Python 3 + `pip install cramjam`):

```sh
python3 test/golden/generate.py && moon fmt   # or simply: make generate-golden
```

- The generator is **deterministic** (gzip is written with `mtime=0`), so
  re-running it produces identical bytes — CI relies on this.
- The spliced-batch fixtures also overwrite `golden_test_data_test.mbt`, so
  the emitted module is re-run through `moon fmt` (block style) before
  committing.

Any diff in these bytes is expected to be committed alongside a codec change.
CI (`golden` job) re-runs the script + fmt and fails if the committed files
diverge.
